# Руководство пользователя Pendulum

Pendulum — анализатор сеточных (grid) стратегий для спотового рынка. Он загружает историю свечей,
прогоняет сетки через консервативный симулятор, подбирает параметры по walk-forward, ранжирует пары и
ведёт paper-trading на живых данных. Реальных ордеров анализатор не выставляет: доступ к бирже
только на чтение.

---

## Что НЕ делать

- ❌ Не создавать API-ключ с правами **Trade**, **Withdraw**, **Transfer**. Если ключ нужен, то только **Read-Only**.
- ❌ Не коммитить `.env` и не отправлять ключи и токены в чаты или на скриншоты.
- ❌ Не воспринимать результаты бэктеста как обещание прибыли: это симуляция на истории.
- ❌ Не выполнять `docker compose ... down -v` во время длительного paper-теста: команда удалит БД
  вместе с историей и сессиями.

---

## 1. Подготовка окружения

- [ ] 1.1. Docker с Compose v2: проверь, что работают `docker --version` и `docker compose version`.
      На Windows используй Docker Desktop с интеграцией WSL2.
- [ ] 1.2. Docker должен запускаться без `sudo`: `docker run --rm hello-world`.
- [ ] 1.3. Для разработки установи [uv](https://docs.astral.sh/uv/). Python 3.12 он поставит сам.
- [ ] 1.4. Оставь свободное место: минутные свечи за год занимают около 0.5 ГБ на пару.
      Для walk-forward нужно 1–2 ГБ свободной оперативной памяти.

## 2. (Необязательно) Read-only ключ Bybit

Публичные данные (свечи, параметры пар, тикеры, поток сделок) Bybit отдаёт без ключа. Ключ нужен только
для того, чтобы подтянуть твою реальную ставку комиссии. Без ключа комиссия берётся из `.env` (по
умолчанию 0.1% maker и taker).

- [ ] 2.1. Bybit → аватар → **API** → **Create New Key** → **System-generated API Keys** → **API Transaction**.
- [ ] 2.2. Права: только **Read-Only**.
- [ ] 2.3. Скопируй Key и Secret в менеджер паролей. ⚠️ Secret показывается один раз.

## 3. (Необязательно) Telegram-уведомления

- [ ] 3.1. [@BotFather](https://t.me/BotFather) → `/newbot` → получи токен `TELEGRAM_BOT_TOKEN`.
- [ ] 3.2. Открой своего бота и нажми **Start**.
- [ ] 3.3. Открой `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates` и найди `"chat":{"id":...}`.
      Это `TELEGRAM_CHAT_ID`.

⚠️ Если токен утёк: @BotFather → `/revoke`, затем обнови `.env`.

## 4. Файл `.env`

- [ ] 4.1. Скопируй шаблон: `cp .env.example .env`.
- [ ] 4.2. Задай как минимум `POSTGRES_PASSWORD`. По желанию заполни ключ Bybit и `TELEGRAM_*`.
- [ ] 4.3. Ограничь доступ к файлу: `chmod 600 .env`. Проверь, что git его игнорирует:
      `git check-ignore .env` должен вывести `.env`.

Все параметры описаны в разделе Configuration файла `README.md`.

## 5. Запуск и работа

```bash
make up          # сборка, миграции, сборщик данных, воркеры, расписание, paper-trader
make ps          # все сервисы (healthy); migrations — Exited (0)
```

| Задача | Команда |
|---|---|
| Загрузить историю | `make data-load ARGS="--pairs BTC/USDT,SOL/USDT --since 2025-10-01"` |
| Бэктест одного набора | `make backtest ARGS="--pair SOL/USDT --since 2026-01-01 --levels 20 --width 16"` |
| То же с фильтром тренда | `make backtest ARGS="--pair SOL/USDT --since 2026-01-01 --regime er168"` |
| Walk-forward подбор | `make walk-forward ARGS="--pairs BTC/USDT,SOL/USDT --since 2025-10-01"` |
| Walk-forward с фильтрами | `make walk-forward ARGS="--pairs SOL/USDT --since 2024-01-01 --grid regime --workers 3"` |
| Рейтинг пар | `make scan` |
| Сводка paper-trading | `make paper-summary` (за неделю: `ARGS="--days 7"`) |
| Paper против бэктеста | `make paper-compare` |
| Логи paper-trader | `make paper-logs` |
| Остановить стек | `make down` (данные сохраняются) |

Отчёты сохраняются в `docs/reports/backtests/`, `docs/reports/walk-forward/` и `docs/reports/paper/`.

**Paper-trading** открывает виртуальные сетки по парам из `config/pairs.toml` (`enabled = true`).
После перезагрузки достаточно выполнить `make up`: сессии продолжатся, пропущенное время досчитается по
минутным свечам. Пара, остановленная по стоп-лоссу, остаётся остановленной. Чтобы открыть её заново,
запусти `pendulum paper run --rearm`.

**Telegram** присылает сообщения о старте сессий, выходе цены из диапазона, остановке, а также
ежедневную (00:05 UTC) и еженедельную (по понедельникам) сводки.

## 6. Как читать результаты

- **Net / Annual:** итог после всех комиссий и проскальзывания, остаток монеты оценён по рынку.
- **Realized / Unrealized:** прибыль закрытых кругов и результат по остатку монеты. Большой отрицательный
  Unrealized означает «мешок», накопленный при падении цены.
- **B&H:** результат простого удержания монеты за тот же период.
- **Max DD:** максимальная просадка капитала, с учётом минимумов внутри свечи.
- **Walk-forward:** важны только out-of-sample окна. Большой разрыв между in-sample и out-of-sample
  результатом — признак подгонки параметров под прошлое.
- **Viability check:** набор строгих критериев (доля плюсовых окон, годовая доходность против B&H,
  просадка, устойчивость по окнам и парам). Пороги задаются в `pendulum/backtest/criteria.py`.
