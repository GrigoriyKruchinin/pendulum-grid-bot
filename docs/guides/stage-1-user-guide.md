# Гайд пользователя: Стадия 1 (MVP + сбор данных, без реальных денег)

Цель Стадии 1: проверить на истории и на живых данных (paper-trading), зарабатывает ли grid-бот на парах
Bybit после всех комиссий и лучше ли он простого удержания монеты. **Никаких реальных сделок на этой стадии нет.**

Всё запускается локально на твоём ноутбуке (WSL2 + Docker). Сервер (VPS) понадобится только на Стадии 2.

---

## Что НЕ делать

- ❌ Не создавать ключ с правами **Trade**, **Withdraw** (вывод), **Transfer**, **Sub-account** и т.п.
  На Стадии 1 нужен только **Read-Only**.
- ❌ Не отправлять ключи, секреты и токены в чат, в issues, в коммиты, на скриншоты.
- ❌ Не коммитить файл `.env` (он уже в `.gitignore`; проверяй `git status` перед коммитом).
- ❌ Не пополнять счёт ради Стадии 1: бот ничего не покупает и не продаёт.
- ❌ Не воспринимать результаты бэктеста как обещание прибыли: это симуляция на истории.

## Шаг 1. Аккаунт Bybit и read-only API-ключ

> Публичные свечи Bybit доступны и без ключа. Read-only ключ нужен, чтобы бот получил **твою реальную ставку
> комиссии** (зависит от VIP-уровня) и чтобы проверить работу аутентификации до Стадии 2.

- [ ] 1.1. Войди в аккаунт на [bybit.com](https://www.bybit.com) (основной аккаунт, не субаккаунт).
      Если аккаунта нет, зарегистрируйся и пройди KYC.
      ⚠️ Проверь, что Bybit обслуживает твою комбинацию «страна проживания (Аргентина) + гражданство» на этапе KYC:
      правила меняются. Если будут сложности, скажи мне: архитектура позволяет переключиться на другую биржу.
- [ ] 1.2. Включи двухфакторную аутентификацию (Google Authenticator), если ещё не включена.
- [ ] 1.3. Открой: аватар (правый верхний угол) → **API** → **Create New Key** → **System-generated API Keys**.
- [ ] 1.4. Тип ключа: **API Transaction**. Название: например, `pendulum-stage1-readonly`.
- [ ] 1.5. Права (API Key Permissions): выбери **Read-Only**. Никаких галочек в разделах Trade / Withdraw /
      Transfer / Assets не ставь.
- [ ] 1.6. IP-ограничение: для read-only ключа на домашнем ноутбуке можно выбрать **No IP restriction**
      (домашний IP обычно меняется).
      ⚠️ У Bybit ключи без привязки к IP действуют ограниченный срок (обычно 3 месяца), потом ключ нужно
      пересоздать. Для Стадии 1 это нормально; на Стадии 2 ключ будет привязан к IP сервера.
- [ ] 1.7. Подтверди создание кодом 2FA. Скопируй **API Key** и **API Secret** в менеджер паролей.
      ⚠️ Secret показывается один раз.
- [ ] 1.8. Проверь в списке ключей, что у нового ключа стоит **Read-Only**.

## Шаг 2. Telegram-бот для уведомлений

- [ ] 2.1. Открой в Telegram [@BotFather](https://t.me/BotFather) → отправь `/newbot`.
- [ ] 2.2. Укажи имя (например, `Pendulum Alerts`) и username, оканчивающийся на `bot`
      (например, `pendulum_<что-то>_bot`).
- [ ] 2.3. BotFather пришлёт токен вида `123456789:AA...`. Это `TELEGRAM_BOT_TOKEN`. Сохрани в менеджер паролей.
- [ ] 2.4. Найди своего бота по username и нажми **Start** (или отправь ему любое сообщение).
      Без этого бот не сможет тебе писать.
- [ ] 2.5. Узнай свой `TELEGRAM_CHAT_ID`: открой в браузере
      `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates`
      (подставь токен вместо `<TELEGRAM_BOT_TOKEN>`). В ответе найди `"chat":{"id":123456789,...}`:
      число и есть `TELEGRAM_CHAT_ID`.
      Если ответ пустой (`"result":[]`), отправь боту ещё одно сообщение и обнови страницу.
- [ ] 2.6. (Необязательно) В @BotFather: `/setprivacy` → Enable, `/setjoingroups` → Disable, чтобы бота
      нельзя было добавить в чужие группы.

⚠️ Если токен утёк: @BotFather → `/revoke` → выбери бота → получи новый токен и обнови `.env`.

## Шаг 3. Локальное окружение (WSL2)

- [ ] 3.1. Docker: убедись, что работают обе команды:
      ```bash
      docker --version
      docker compose version
      ```
      Если `docker compose` не найден, установи Docker Desktop с включённой интеграцией WSL2
      (Settings → Resources → WSL Integration) или плагин `docker-compose-plugin` для Docker Engine.
- [ ] 3.2. Проверь, что Docker запускается без `sudo`: `docker run --rm hello-world`.
- [ ] 3.3. `uv` уже установлен (`~/.local/bin/uv`). Обнови до свежей версии: `uv self update`.
      Python 3.12 для проекта `uv` поставит сам; системный Python 3.10 трогать не нужно.
- [ ] 3.4. Освободи ~5 ГБ на диске под базу свечей (1-минутная история по 15–20 парам за 1–2 года).

## Шаг 4. Файл `.env`

- [ ] 4.1. В корне репозитория:
      ```bash
      cp .env.example .env
      ```
- [ ] 4.2. Заполни в `.env` (только в `.env`, не в `.env.example`!):
      ```dotenv
      POSTGRES_PASSWORD=<придумай-длинный-пароль>
      EXCHANGE_ACTIVE=bybit
      EXCHANGE_BYBIT_API_KEY=<твой-read-only-api-key>
      EXCHANGE_BYBIT_API_SECRET=<твой-read-only-api-secret>
      EXCHANGE_BYBIT_TESTNET=false
      TELEGRAM_BOT_TOKEN=<токен-от-BotFather>
      TELEGRAM_CHAT_ID=<твой-chat-id>
      ```
      Остальные значения можно оставить по умолчанию (капитал $500, до 30% на пару, геометрическая сетка).
- [ ] 4.3. Проверь, что `.env` не попадёт в git:
      ```bash
      git status --short    # .env не должен появиться в списке
      git check-ignore .env # должно вывести: .env
      ```
